# T-0485 R10 — Dormant connected broker client gate

**Scope:** `wake/src/install_broker_client.rs` and the Wake library export. No installed service, protected namespace, Wake launch selector, install guard, approval issuer, or runtime mutation path changed. The production `WAKE_INSTALL_BROKER_UNPROVISIONED` holds remain.

The client opens only the compiled local `\\.\pipe\CatDeskWakeInstallBrokerV1` name with the exact operator mask `0x00120083` (data read/write, read attributes, `READ_CONTROL`, synchronize; no `FILE_CREATE_PIPE_INSTANCE` bit `0x4`) and explicit impersonation SQOS. It sends **zero application bytes** while it inspects the *connected handle*: exact protected pipe owner/DACL, message type and one-instance mode, Windows-reported server PID and session 0, fixed SCM service in `SERVICE_RUNNING`/own-process with the same PID, and a pinned live process handle with stable creation time. A bounded process-token parser requires `TokenUser=LocalSystem`, primary token, session 0, System integrity, no AppContainer, a restrictions flag, and the fixed service SID both enabled in `TokenGroups` and present in `TokenRestrictedSids`. The process executable path is checked against the compiled service image path; the fixed Program Files image object is pinned without write/delete sharing and checked against independent preflight object ID and SHA-256 readback.

`FixedBrokerApprovalClient::write_one_approval` consumes that connected pipe/process/service/image guard, repeats policy, SCM, process, token, image and pipe readback, then performs one overlapped message write on the **same** handle. A timeout or short write reports indeterminate delivery; callers must consult the protected ledger before any retry. No separate success Boolean can authorize a later connection. The broker must still independently check operator impersonation, signature, staged bytes, replay ledger and predecessor state.

**Focused Windows evidence:** `cargo test --locked --offline --manifest-path wake/Cargo.toml --lib install_broker_client` passed 4/4. The isolated same-user name-squat fixture connected to a unique nonproduction pipe and showed that its descriptor failed the exact protected descriptor check while `PeekNamedPipe` observed **zero bytes**. A separate live fixture received exactly one message from the overlapped write path. Pure negatives reject wrong SCM state/type/PID/flags and malformed, disabled or out-of-buffer token-group entries. `cargo clippy --locked --offline --manifest-path wake/Cargo.toml --all-targets -- -D warnings` and Wake formatting passed locally. These fixtures do not prove a positive connection to a provisioned SYSTEM broker; none is installed here.

**Live integration limits:** The installed policy file and fixed service image parent/file must grant the interactive operator exact read-only access, and the SCM service descriptor must permit query configuration/status and `READ_CONTROL`; the corresponding R8/R2 source policies now express these rights without write/delete/owner/ACL access. Microsoft documents that querying a process token belonging to another account can require `SeDebugPrivilege`. This client does not enable that privilege and fails closed if an elevated operator cannot query the SYSTEM service token; a provisioned-service fixture must settle feasibility or a separately reviewed server-attestation mechanism must replace it. `QueryFullProcessImageNameW` supplies the process's recorded path, not the historical loaded image-section file ID. The protected file identity/hash therefore corroborates the separately signed bootstrap but does not by itself prove that the running process loaded those exact bytes. The fixed first-instance endpoint and client checks limit same-user squatting; they do not substitute for signed broker bootstrap, token-denial tests, or exact-commit CI.
