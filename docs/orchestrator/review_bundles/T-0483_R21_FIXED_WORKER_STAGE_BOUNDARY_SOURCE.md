# T-0483 R21 — Fixed worker binding required at the host stage boundary (source only)

**Scope:** `src/delegated/sol_worker_staging.rs` and the narrow delegation method in `src/delegated/sol_worker_identity_preflight.rs`. The code remains dormant: there is no Sol launch, repository write, account provisioning, review event, or Wake receipt.

The crate-visible root audit now consumes the opaque `BoundFixedLocalSolWorkerProcessV1` from R20. It revalidates the pinned live process and fixed local account, rejects host/SYSTEM token trustees, and audits the opened staging root against the observed `TokenUser`. The resulting root type retains that same binding. The only crate-visible stage function takes that root type and a burned Sol output; its returned stage retains the binding and repeats validation before and after readback. An observed restricted token alone can no longer enter this stage path.

The caller-supplied-SID root audit and bare `PinnedSolWorkerStageV1` are now private to the staging module. They remain as implementation and fixture helpers for ACL, manifest, collision and tamper checks, but another module cannot obtain a stage or readback through them. A type-signature test pins the two crate-visible function inputs and the fixed-worker stage readback type. A real current-host process fails the fixed-worker binding before it can reach the stage API.

**Local verification:** 11/11 focused Windows staging tests passed, including the type-signature and real-host refusal checks. The 8 fixed-account tests passed. Strict all-target/all-feature Clippy, repository formatting, and diff checks passed. The fixed `CatDeskSolWorker` account is absent on this host, so no positive real worker binding or stage run through this stronger path was possible.

**Remaining boundary:** R20 proves a fixed-account match for one currently live opened process, not a trusted Codex launch or loaded image. There is still no worker lifecycle owner, descendant-exit and inherited-handle proof, complete ancestor ACL/rename exclusion, account-membership atomicity, or durable burn-to-stage transaction. Readback currently requires that process to remain live, while a future repository-use path must prove that the worker and descendants have stopped and lost write authority; that lifecycle handoff requires a separate design and test before use. No repository mutation accepts this stage today, and P1 is not accepted.
