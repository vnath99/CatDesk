# T-0485 R4 — Dormant protected broker transaction ledger

**Scope:** `wake/src/install_broker_ledger.rs`, Wake library export and small approval-value accessor changes. This source is not a broker service, protected namespace bootstrap, package writer, activation path or release approval.

A future fixed broker must supply an already pinned, independently protected root and a pre-provisioned global lock file. The module holds that file without sharing across a bounded handle-relative inventory and one transaction. It reopens a fresh directory FILE_OBJECT relative to the pinned root and checks its physical ID before the first filtered NT query; an earlier query on the caller's handle cannot hide records. It rejects later or missing middle generations, corrupt or incomplete historical records, a reused approval ID or signed approval digest, a changed predecessor/root, a concurrent contender and out-of-order phases before a fresh intent. Create-once canonical records bind generation, approval/package/manifest, predecessor pointer, original desired host state, original physical owner observations and prior-phase digest. Each phase is flushed and read back; reopening validates the whole chain and never erases a torn record. Duplicate phase calls revalidate the on-disk record. No path from an installer request selects a ledger file.

An exact resume API cryptographically rechecks the original signed envelope against the protected first-acceptance time and original object observations, including after expiry; it does not create intent or authorize a new transaction. The current state still needs physical reconciliation for its recorded phase before any side effect.

This is **not** a durable install transaction yet. The protected bootstrap and effective ACL/integrity/worker-denial proof for the root and lock are absent. Parent-directory metadata survival across power loss is unproven. A valid first generation on an empty ledger needs independent dev.84 physical-state migration evidence. The future broker must supply a trustworthy clock and independently recheck actual package bytes, pointer and owner at every mutation/recovery step, then safely restore the original desired state. No install mutation is connected to this ledger.
