# T0478 R3B4-C1 — Manifest-bound isolated MCP dispatch

Date: 2026-10-14. This is a source-level bridge from a producer-held `StagedCandidateSnapshot` to the existing isolated MCP read/search dispatcher. It is not a live launcher or an accepted T0478-C worker.

`handle_isolated_fixture_request_with_snapshot` routes only the existing isolated `read` and `search` tool calls through `StagedCandidateSnapshot::read_manifest_leaf`. The snapshot retains the in-process validated manifest and pinned root; the method opens the requested leaf through the protected no-follow single-link reader and verifies its exact size and SHA-256 before either tool sees bytes. JSON-RPC cannot provide or replace a manifest. Other methods reuse the restricted fixture surface, and unknown tools remain denied. The existing pathname-based fixture handler remains for the older disposable development mode; serving a reviewed candidate must use the snapshot-backed entry point.

Windows tests exercise both tools with a manifest-approved leaf, then reject an unlisted leaf, changed bytes, and a newly injected leaf. A separate test verifies the existing retained file lease prevents an ordinary same-user rewrite while the snapshot is alive. The adversarial mutation test intentionally omits retained leases to prove the per-request digest check remains effective if write sharing is possible.

The Axum handler requires a `Send` future. Keeping a raw-handle snapshot reference across the async tool-list await broke compilation, so the snapshot-backed tool call is completed synchronously before the legacy async initialize/list path. This change does not assert that the raw-handle snapshot itself is safe to share across server worker threads.

Local focused and full Rust results, formatting, strict Clippy and exact-commit CI status are recorded in the milestone log. Remaining T0478-C work: bind the snapshot into the real isolated HTTP server state for its entire listener lifetime, prove thread-safe pinned-handle ownership without unsound trait shortcuts, deny the old pathname path for reviewed candidates, enforce owner/DACL and root identity throughout serving, and run real HTTP adversarial tests. T0478-D process ownership and T0479 versioned worker/LKG follow. GitHub Actions currently rejects dispatch with HTTP 422 (`Actions has been disabled for this repository`), so independent three-job Windows CI acceptance is pending.
