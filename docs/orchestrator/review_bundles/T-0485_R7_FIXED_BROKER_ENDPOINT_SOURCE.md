# T-0485 R7 — Dormant fixed broker pipe endpoint

**Scope:** `wake/src/install_broker_endpoint.rs`, a small fixed-service-SID preflight helper and Wake library export. No service or request client is running, and no install guard was changed.

The production constructor has a compiled `\\.\pipe\CatDeskWakeInstallBrokerV1` name and requires an opaque `ProvisionedOperatorSid` value with **no current production constructor**. It first requires the fixed broker preflight. It then creates one non-inheritable, first-instance, local-only message pipe with a protected explicit DACL: SYSTEM and the broker service SID have server rights, while the operator has only data read, data write, read attributes and synchronize. The operator mask excludes `FILE_CREATE_PIPE_INSTANCE`, which shares a bit with file append/write generic mappings. The module independently reads back owner, protected DACL, pipe type and instance count from the opened endpoint. It returns only a diagnostic identity snapshot.

Five focused Windows endpoint tests pass for an isolated current-user fixture, wrong owner/operator descriptor readback, policy rejection, first-instance collision, a real duplex client connection with the exact operator mask, OS denial of a second server instance to that operator-only client, and operator-only name-squat behavior. Independent source review found no concrete constructor/DACL/FFI bypass. The name-squat test shows that another user-context process can create a pipe with the fixed name before the service starts. First-instance creation makes the genuine service fail closed in that case; future clients must also authenticate the **connected server process/image/token** before sending approval bytes, since a name alone does not authenticate a server.

**Remaining:** provision and verify the separately signed service image, protected operator policy, owner/DACL and complete ancestor effective-access/integrity/worker denial. The service must serialize each request read with connected-client impersonation and signed approval/ledger checks. The endpoint readback neither authorizes installation nor validates a client or server at runtime. Legacy launch selection, protected transaction, dev.84 physical migration and exact-source Windows CI remain hard gates for dev.85.
