# T-0483 R20 — Fixed-account to opened Sol worker process binding (source only)

**Scope:** `src/delegated/sol_worker_identity_preflight.rs` and `sol_worker_token_security.rs`. This code is dormant. It does not provision an account, acquire credentials, launch Codex, stage output, or open the Sol workspace-write guard.

`bind_fixed_local_sol_worker_to_opened_process` returns an opaque value only after the fixed local `CatDeskSolWorker` preflight, the already opened process's actual restricted **primary** token readback, an exact `TokenUser` SID match, a second complete account preflight, and a final token revalidation. Its `revalidate` checks the pinned token, repeats the fixed account lookup and group/flags policy, compares the complete bounded account snapshot (including sorted indirect local-group names and account flags), and checks the token again. The caller cannot construct this value from a supplied account or token SID. A same-count group membership change and an account flag change now invalidate it.

The existing opened-token observer now requires an actual live process. It duplicates and pins the caller's process handle, records its PID and creation time, and reopens that PID with `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`. It compares the reopened process's PID and creation time and checks both process handles are nonsignaled with a zero-time wait. The checks repeat on token revalidation, alongside the existing fresh process-token and pinned-token snapshot comparison. An exited process is refused even while its original process handle remains open. `WaitForSingleObject` requires the supplied handle to have `SYNCHRONIZE` access; lack of access fails closed.

The handle rights and API shape follow [Microsoft's process access-rights reference](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights), [`GetProcessTimes`](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes), and [`WaitForSingleObject`](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject). `GetProcessTimes` accepts limited query access; the zero-time wait requires `SYNCHRONIZE` and returns `WAIT_TIMEOUT` only while the process object is nonsignaled.

Fixed-account/preflight tests **8/8** passed, including fixed-account-versus-host/SYSTEM token SID mismatch, account SID/flags/group changes, refusal to bind the real host process, and the real absent-account fail-closed diagnostic (`NERR_UserNotFound` 2221). The broader `sol_worker_` bin filter passed **45/45**. Strict all-target/all-feature Clippy passed; repository formatting and diff checks passed. The fixed worker account is absent on this host, so a positive real restricted worker process binding could not be exercised.

**Remaining boundary:** this evidence is only a read-only snapshot. It does not prove the caller supplied the process created by a trusted Sol launch, identify its image, prevent its exit immediately after validation, atomically lock account membership across NetAPI calls, or prove descendant exit, inherited-handle removal, staging ancestor rights, and complete lost write authority. The existing process-bound stage API still accepts a token observation without this new fixed-account binding; future lifecycle integration must require the stronger value at the repository-use boundary. No real Sol deliverable, review, or Wake cycle was accepted.
