# T-0485 R5 — Dormant connected operator-token admission

**Scope:** `wake/src/install_broker_operator.rs` and the Wake library export. The module does not create a service or pipe endpoint and is not an install authority.

The future fixed broker can call `inspect_connected_pipe_operator` on the actual connected named-pipe instance, after receiving a request and before decoding it. The check rejects a thread that was already impersonating, calls `ImpersonateNamedPipeClient`, opens the resulting thread token, bounds and reads its embedded `TokenUser` and integrity SID, and requires the exact protected-policy operator SID, high-or-higher integrity, an elevated interactive session, impersonation/delegation level, no AppContainer and no token restrictions. `TokenHasRestrictions` is queried fail closed, including filtered tokens; the real Windows fixture returned a one-byte value despite the documented DWORD, so the bounded parser accepts only exact one- or four-byte results and denies any nonzero value. A drop guard aborts the process if `RevertToSelf` fails. It returns bounded identity evidence only after the token check; no PID, image name, JSON field or same-user path authorizes an install.

Seven Windows focused tests pass, including a real local named-pipe client-token/revert fixture and negative policy tests for wrong user, SYSTEM policy, low integrity, unelevated/session-zero, identification-only impersonation, AppContainer, restricted token and malformed SID. The real fixture validates its own same-process client connection; it does not exercise the future service endpoint DACL or a provisioned operator account.

**Remaining:** the expected SID must be read from an independently protected, pinned broker policy; a fixed endpoint DACL must be created/read back; the signed service must serialize each request's read and this check on one connected pipe instance, then decode/act without another read/disconnect/reconnect, because Windows impersonates the sender of the last message read. Evidence cannot be reused for a later request. Worker/descendant denial plus inherited-handle probes must run under actual tokens. This result cannot clear `WAKE_INSTALL_BROKER_UNPROVISIONED` or authorize dev.85. Exact-source three-job Windows CI, source review, signed approval and protected transaction remain separate gates.
