# T-0485 R15 — Fixed source to protected STAGED transaction (source only)

## Implemented

- `install_broker_source.rs` opens only the compiled `C:\ProgramData\CatDesk\WakeSubmissionV1\candidate` path. It pins the ancestor chain and exactly `manifest.json`, `CatDeskWakeHost.exe`, `CatDeskBinagotchy.exe`, `adapter.py` and `wake_bridge.py`; rejects reparse points, hardlinks, aliases, extra entries, changed bytes and wrong signed hashes; and reopens fixed names before use. The inbox is untrusted.
- `BrokerLedgerGuard::accept_with_observation` acquires the pre-provisioned global ledger lock before invoking the future observer. It verifies the envelope against the pinned protected policy key and writes INTENT. The new opaque `PolicyVerifiedApprovalV1` prevents a bare value checked with an arbitrary key from entering the production ledger or stage writer. The callback still needs a real kernel-backed service implementation and retained object/process pins; its type alone does not prove provenance.
- INTENT and later ledger records bind the exact signed envelope digest, protected policy file identity and byte digest, and verification-key digest. STAGED receipt checks the same policy snapshot. The read-only exact-resume verifier rejects a replacement signature or a rotated key even when the signed payload is unchanged; it does not grant a production recovery lease.
- `install_broker_stage_writer.rs` creates only the fixed protected `staging/candidate` slot with `FILE_CREATE` and explicit SYSTEM/service security, copies the four signed artifacts in bounded chunks, flushes them and the canonical manifest, then reopens and hashes the exact slot. A typed receipt retains source and stage pins and revalidates physical IDs/bytes before `record_staged`. The ledger records all seven stage object IDs in `STAGED`. Any residual or partial candidate is sticky attention and cannot be reused or silently deleted.
- There is no package publication, pointer switch, old-owner stop, new-owner launch or production install caller. Both install mutator holds remain `WAKE_INSTALL_BROKER_UNPROVISIONED`.

## Verification and limits

- Focused Windows tests exercise source shape/hash/alias/hardlink refusal, bounded copy, policy wrong-key rejection, same-payload policy-key rotation refusal and observation-under-lock, a temp-root `INTENT → fresh copy → typed STAGED → exact reopen` transaction, and residual partial-stage refusal with no STAGED record. The integrated fixture uses a test-only owner/security mode; it does not prove actual SYSTEM-owned production ACL creation.
- Full independent Wake Rust suite, strict all-target Clippy, formatting and diff checks passed locally on the uncommitted source; final combined root/Python gates and exact SHA Windows CI are tracked separately. No installed/protected namespace was touched.
- Remaining gates: independently signed and provisioned fixed service/namespace/key/lock, trusted observation and clock provenance, independent exact push-CI fetch, parent-directory power-loss durability and durable orphan attention, first-generation dev.84 physical reconciliation, policy-bound resume under the global lock with current-phase checks, approved immutable package/pointer/owner transaction, launch-reader cutover, signed release and new Chat53 canary. A `STAGED` record alone grants no install authority.
