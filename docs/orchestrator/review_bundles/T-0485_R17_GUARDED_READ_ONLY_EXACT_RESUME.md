# T-0485 R17 — Guarded read-only exact-resume inspection (source only)

## Implemented

- `BrokerLedgerGuard::inspect_exact_resume` retains the pre-provisioned global lock from ledger inventory through policy verification, current observation and final stage readback. It requires an existing exact INTENT, validates the latest generation and complete history, and compares the signed envelope, protected policy file identity and bytes, and verification key with the original INTENT. It never creates a ledger record, flushes a directory or returns a lease.
- A future broker-owned observer must report the current clock, predecessor pointer, protected root, old runtime root/lock, old host image/hash, PID/creation time and original desired state while the lock is held. Any drift or clock rollback refuses the readback. Reverification uses the original protected acceptance time, so an expired approval can diagnose only its original transaction.
- INTENT requires empty protected staging. STAGE_STARTED reports sticky attention even with no candidate or a partial candidate. STAGED rehashes the fixed five-file candidate with protected ACL and inventory checks, then matches all seven physical IDs against the STAGED ledger record. Later phases refuse inspection until their physical effects have explicit reconciliation.
- The result and the stage reader both retain `NO_INSTALL_AUTHORITY` dispositions. The stage reader's creation/provenance flag stays false; the combined ledger-ID match is a point-in-time diagnostic, not a publication, activation or recovery capability. Production `record_staged` still requires the writer's opaque pinned receipt; only tests can synthesize a stage binding.

## Verification and limits

- Three new integrated policy/ledger tests cover missing INTENT with no create, expired exact readback under the lock, wrong and rotated keys, current predecessor/desired-state drift, clock rollback, future-generation residue, INTENT orphan refusal, STAGE_STARTED attention after an injected parent-flush failure and with a partial candidate, STAGED exact readback, changed bytes, extra entries and identical-byte physical file replacement. Fixture cleanup verifies the root physical ID and removes only known leaves and empty directories.
- The full Wake Rust suite passed locally: 161 library tests plus binary/integration tests, with two existing manual diagnostics ignored. The three R17 tests passed again after the final test-only file-drift adjustment. Strict all-target, all-feature Wake Clippy, formatting and diff checks passed locally.
- The test-only stage inspector uses the fixture's owner/security; production requires the fixed SYSTEM/service ACL policy. The final readback rechecks this generation and policy, while prior generations rely on the global lock and protected writer ACL after their initial validation. A noncooperating writer with protected-ledger write access could change earlier history during the readback; the result grants no authority. No installed broker, trusted observer/clock, independently fetched exact CI, protected launch/pointer/owner transaction or real protected-stage restart was exercised. The current source still has no signed service/bootstrap and no power-cut proof for the target storage. Both production install mutation holds remain `WAKE_INSTALL_BROKER_UNPROVISIONED`.
