# T-0485 R8 — Dormant protected broker policy loader

## Scope

`wake/src/install_broker_policy.rs` adds a zero-argument, read-only loader for the compiled `C:\ProgramData\CatDesk\WakeProtectedInstallV1\broker-policy.json`. The fixed preflight must first validate the separately installed SCM service and pinned protected root. The loader opens the policy by its fixed name relative to that pinned root, without following a reparse point or allowing write/delete sharing. It accepts one regular, single-link file on the root volume. The root and policy file must have their exact SYSTEM-owned DACLs, and the canonical policy must bind both physical object IDs. The policy file grants SYSTEM and the restricted service SID full access, plus IU read-only `0x00120089`, so an interactive client can inspect the public verification key and SIDs but cannot write the policy. The image parent/file and SCM service descriptors likewise grant only the exact IU query/read rights required for interactive client preflight.

The 4,096-byte maximum JSON wire has one version and purpose, the physical root and file IDs, the fixed service SID, an exact account SID for the operator, and a 32-byte Ed25519 approval public key in lowercase hex. Unknown, duplicate, reordered and noncanonical encodings fail. The operator SID must resolve as `SidTypeUser`; the key must parse as a nonweak Ed25519 verification key. The returned `BrokerProtectedPolicyV1` is opaque: production callers cannot construct it from a supplied path, key, SID or JSON. It keeps the handles pinned and rechecks root/file IDs, owner/DACL and exact bytes through both the original handle and a fresh fixed-name reopen before a readback or use.

The approval verifier consumes the key only through this policy value. The fixed endpoint constructor consumes the same pinned service/operator SIDs; its operator ACE now includes `READ_CONTROL` for connected-client descriptor readback, while still excluding the pipe-create-instance bit. The single-message receive path can perform connected-client impersonation with the policy SID immediately after its final pipe read, without a policy file read in between, then revalidate the policy after admission. None of these source modules install a service, create ProgramData state, sign an approval, or grant package mutation.

## Focused verification

- `cargo test --locked --offline --manifest-path wake/Cargo.toml --all-features install_broker_policy::tests -- --nocapture`: **8 passed** on Windows. Fixtures cover valid pinned load, canonicality and byte bound, wrong purpose/root/file/service, weak key and group operator, hardlink and ACL mismatch, reparse metadata, held-pin write/delete refusal plus exact-byte revalidation, and a real IU read-only DACL that permits the policy open while refusing `FILE_WRITE_DATA`.
- `cargo test --locked --offline --manifest-path wake/Cargo.toml --all-features install_broker_preflight::windows::tests -- --nocapture`: **3 passed** after the client-read policy adjustment, including exact rejection of an insufficient IU SCM ACE and a missing IU image ACE.
- `cargo test --locked --offline --manifest-path wake/Cargo.toml --all-features install_broker_endpoint::tests -- --nocapture`: **5 passed** after the operator mask change, including a real narrow-rights client exchange and OS denial of a second server instance.

## Remaining production gates

This loader proves a read-only snapshot under the proposed owner/DACL policy. A privileged, separately reviewed bootstrap must install and sign the fixed broker image, create the protected namespace and policy, establish the independent approval trust root and read them back. Source cannot prove that the policy key came from the offline approval authority. The preflight still lacks complete ancestor effective-access/integrity and actual worker/descendant-token denial, including inherited-handle probes. The separately installed service must serialize the last request read with connected-client admission, independently verify exact CI and approval, and bind package/pointer/ledger/owner effects. The client must authenticate its connected server before sending an approval. Legacy launch/status/recovery selectors, dev.84 physical reconciliation, exact-source Windows CI and the full transaction remain open. Both `WAKE_INSTALL_BROKER_UNPROVISIONED` production holds remain unchanged.
