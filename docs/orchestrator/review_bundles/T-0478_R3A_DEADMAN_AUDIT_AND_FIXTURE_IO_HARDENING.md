## R3A narrowly scoped improvement

- New `windows_protected_fs::read_relative_regular_unique` opens one no-follow regular file **relative to its pinned directory handle**, requires Windows `number_of_links == 1`, enforces a 512 KiB bound, reads once from that handle and checks retained parent stability. Existing general CatDesk file-access APIs are unchanged.
- `mcp::handle_isolated_fixture_request` now routes fixture-only `read` and `search` through an isolated file-data path. It accepts ONLY one plain regular file basename at the fixture root (never `config.toml`, leading-dot names, directories, absolute or traversal paths). A symlink/reparse file, hardlinked file and name outside the fixture are refused. Files are read from the single pinned no-follow handle.
- Search now scans the bounded in-memory content via Rust's regex engine; it never resolves or spawns `rg`/`grep` from ambient PATH, and does not follow directories or glob/context options. Search's fixture tool schema requires an explicit `path`. The production `search` MCP API remains unchanged.
- Focused Windows negative tests prove hardlink to a different temp file is rejected by both read and search, and `config.toml` cannot be read. Real Windows HTTP fixture canary exercises bounded in-memory search, config denial and hardlink denial.
- Local commands: `cargo fmt --all` PASS, strict `cargo clippy --locked --offline --workspace --all-targets --all-features -- -D warnings` PASS, `cargo test --locked --offline --bin catdesk isolated_fixture` 2/2 PASS, `cargo test --locked --offline --test isolated_dev_fixture` 1/1 PASS, entire `cargo test --locked --offline --bin catdesk` 1028 PASS, 0 failed, 26 ignored; `git diff --check` PASS.

It does not confer a security sandbox against malicious same-user processes or supply a trusted source-code copy/provenance manifest, PID/port lifecycle, process isolation, general LLM code-edit permission or independent supervisor recovery.
