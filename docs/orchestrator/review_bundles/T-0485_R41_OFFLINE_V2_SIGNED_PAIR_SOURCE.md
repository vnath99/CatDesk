# T-0485 R41 — Read-only V2 offline Wake anchor and package pair

Date: 2026-10-16. Isolated source baseline `b3427e9f2c4ce6f9e8b8b185e1a71fc6f3dd811f`; R40 protocol `a561fb3`; initial implementation `4ac3411d2c4eb3c4ff8140a7a3e54e9e65bef319`; review-response correction `aabee607e743a6e1492a42b2a05d99e3986a743d`. Status: `IMPLEMENTED_SOURCE_ONLY`, under independent source review and pending integration. This is not an approved migration, provisioned broker, installed dev.85 or natural Wake acceptance.

`wake/src/install_broker_offline_v2.rs` adds separate purpose and Ed25519 domains for a first-generation offline dev.84 anchor and an exact dev.85 package approval. Both envelopes must be bounded canonical JSON with strict fields and signatures under one externally supplied verification key. The V2 package binds the exact anchor envelope digest, generation one, predecessor package/pointer, protected root, candidate manifest, source SHA and the three required push-CI job claims. The anchor compares signed old pointer/root/lock/image, Wake target and paired CatDesk project-registry target, protected broker objects, unresolved-event quarantine, and claimed closed-store/launch-entrypoint inventories with a supplied observation. V1 parsing and replay are untouched. The policy-facing `inspect_offline_pair_read_only` uses the pinned protected approval public verification key and fixed service preflight; the lower-level verifier is crate-private. The only returned value is a digest summary ending `NO_INSTALL_AUTHORITY`.

The comparison observation is **supplied data**, not a retained old-store or launcher proof. Its closed-inventory and quarantine digests can bind a future independently reviewed record but cannot establish that every token-specific `LOCALAPPDATA` store or old launch entrypoint was found and disabled. The current fixed service still returns `WAKE_BROKER_TRANSACTION_GATES_UNAVAILABLE`; ordinary installation still returns `WAKE_INSTALL_BROKER_UNPROVISIONED`. No V2 value enters the ledger, stage writer, pointer writer or service transaction. The old-owner, paired-target, exact CI fetch, protected provisioner, pointer attempt-marker/reader cutover and fresh Chat53 receipt gates remain open. R40 specifies the required future transaction and fail-stop behavior.

The signed `ObjectIdentityV1` fields here are only read-only comparison claims. Their 32-bit volume serial and 64-bit index come from `BY_HANDLE_FILE_INFORMATION`; Microsoft says the 64-bit ID [is not guaranteed unique on ReFS](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information). Release admission needs handle-observed full [`FILE_ID_INFO`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) (or a reviewed filesystem-specific equivalent) bound to the reviewer-authorized roles and retained through INTENT. The present V2 wire/readback has no such field or retained handle, so it remains `NO_INSTALL_AUTHORITY`. A separately mounted immutable old host image may validly have a different volume from the selected runtime root; the read-only verifier compares that signed image claim to the observation without asserting same-volume ownership.
