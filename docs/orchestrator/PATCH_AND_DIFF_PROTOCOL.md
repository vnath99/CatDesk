# Patch And Diff Protocol

Status: T-0013B architecture freeze
Date: 2026-07-25

## Purpose

CatDesk worker edits are patch-first. A worker model may propose changes, but CatDesk validates, applies, compares, records, and verifies them. The actual repository diff is authoritative.

## PatchProposalV1

Required fields:

- `schema_version`
- `patch_id`
- `parent_patch_id`, when revising a previous proposal
- `run_id`
- `turn_id`
- `base_snapshot_hash`
- `target_paths`
- `expected_preimage_hashes`
- `proposed_diff`
- `structured_operations`, when used instead of a raw unified diff
- `model_rationale`
- `claimed_acceptance_criteria`
- `created_by_provider_id`
- `requires_approval`

Validation rules:

- every target path must be relative, allowed by the execution contract, and outside `.git`;
- every pre-image hash must match the file range or file snapshot CatDesk supplied to the provider;
- a patch cannot alter files outside `target_paths`;
- binary edits require an explicit artifact workflow;
- patch IDs are unique within a run;
- a child patch must reference an existing parent patch;
- a patch cannot claim to modify immutable execution-contract fields;
- a patch that needs approval cannot be applied until the approval is recorded and still valid.

## PatchApplicationResultV1

Required fields:

- `schema_version`
- `patch_id`
- `tool_call_id`
- `status`: `APPLIED`, `REJECTED`, `CONFLICTED`, or `OUTCOME_UNKNOWN`
- `actual_paths_changed`
- `before_hashes`
- `after_hashes`
- `rejected_hunks`
- `rejection_reason`
- `resulting_diff_artifact_id`
- `rollback_artifact_id`
- `applied_at_event_sequence`

CatDesk records the result before the next provider turn sees the tool output. If a mutating operation may have happened but the result was not durably recorded, the status becomes `OUTCOME_UNKNOWN` and the runtime must stop for supervisor handling.

## PatchComparisonArtifact

Required fields:

- `artifact_id`
- `run_id`
- `base_patch_id`
- `candidate_patch_id`
- `files_added`
- `files_removed`
- `files_modified`
- `hunks_added`
- `hunks_removed`
- `hunks_changed`
- `changes_superseded`
- `net_line_impact`
- `scope_warnings`
- `base_snapshot_match`
- `associated_verification_results`

Patch comparison is required when a worker revises a patch or when the supervisor asks to compare candidates. It is not a substitute for the final actual Git diff.

## DiffArtifactV1

Required fields:

- `artifact_id`
- `run_id`
- `source`: `MODEL_PROPOSAL`, `PREVIEW`, `ACTUAL_WORKTREE`, or `FINAL_REVIEW`
- `paths`
- `summary`
- `diff_hash`
- `storage_path`
- `truncated`
- `base_commit`
- `head_commit_or_worktree`

The final review package must include an `ACTUAL_WORKTREE` or commit diff generated by CatDesk after edits are applied. Model-proposed diffs are evidence of intent and lineage; they are not authoritative proof of the final state.

## Edit Lifecycle

```text
bounded file read with hashes
-> PatchProposalV1
-> path and hash validation
-> preview diff
-> approval check, when required
-> patch apply
-> PatchApplicationResultV1
-> actual diff artifact
-> focused verification
-> worker receives bounded result
```

## False-Success Protections

CatDesk must reject completion when:

- the model claims a patch was applied but no application result exists;
- the actual diff differs from the recorded patch result without explanation;
- required tests were not run;
- verification is `NOT_CONFIGURED`;
- an `OUTCOME_UNKNOWN` mutation exists;
- unrelated files changed;
- generated artifacts or review bundles were committed contrary to policy;
- the branch has unreviewed user changes that CatDesk did not create.

## Tool Mapping

Patch tools should be separate from raw file writes:

| Tool family | Purpose | Mutation risk |
| --- | --- | --- |
| `read` and `search` | Build bounded context | none |
| `patch.preview` | Validate proposal and produce preview diff | none |
| `patch.apply` | Apply an approved patch | mutating |
| `patch.compare` | Compare two proposals or proposal versus actual diff | none |
| `diff.actual` | Capture authoritative Git/worktree diff | none |
| `verify.run` | Run approved focused or final verification | controlled shell |

Provider adapters never run these tools directly. They request normalized tool calls; CatDesk enforces policy and records results.
