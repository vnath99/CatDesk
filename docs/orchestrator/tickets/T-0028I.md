# T-0028I: Scheduled Reviewer Wake-Up

After a successful autonomous start, CatDesk registers one process-local Tokio
reviewer wake-up for that session. It polls the already owned controller every
30 seconds, preserving the same durable event sequence, contract, lease, and
provider-session state. Duplicate start calls do not create duplicate wake-up
loops.

The wake-up exits on a terminal state, `WAITING_FOR_CHATGPT`, or
`WAITING_FOR_USER`. It does not send unsolicited model prompts, create a new
provider session, invoke a fallback, publish Git changes, or bypass an
escalation. A CatDesk restart uses the persisted controller recovery path
instead of assuming the prior process-local loop survives.

## Reviewer Wake-Up Prompt

An optional ChatGPT-side scheduled reviewer must use only the read-only
autonomy MCP operations: `autonomy_session_list`, `autonomy_session_status`,
`autonomy_session_events`, `autonomy_session_get_escalation`, and
`autonomy_session_get_final_review`. It checks only sessions in
`WAITING_FOR_CHATGPT`, `COMPLETED_VERIFIED`, `FAILED`,
`CREDIT_BUDGET_EXHAUSTED`, or a persisted rate-limit pause.

When no session needs review, it emits no decision and takes no mutation.
When an escalation exists, it reads the bounded packet and may submit one
contract-compliant `autonomy_session_reply` with a fresh decision hash and
idempotency key. It must never approve a merge, force-push, unrestricted
shell, credential access, destructive action, or provider substitution.

This ticket does not create or configure a ChatGPT automation. The process
local wake-up keeps CatDesk's own controller progressing while it is running;
an operator must configure any external reviewer schedule separately.
