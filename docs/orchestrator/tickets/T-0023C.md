# T-0023C MCP-To-Worker Production Wiring And Release-Candidate Gate

Status: COMPLETED_VERIFIED
Date: 2026-07-25
Branch: orchestrator/v1-coding-sprint
Prior ticket commit: 800120d

## Objective

Close the T-0023B review gap by making the supervisor MCP tools create and
start real delegated runs instead of test-only or in-memory placeholder
records. The release-candidate gate required the live worker path to begin
only through MCP `delegated_run_create` and `delegated_run_start`, then observe
state through MCP status, events, and final-review tools.

## Scope Completed

- Changed `delegated_run_create` to require a full `ExecutionContractV1`.
- Validated that the contract workspace matches the MCP workspace and that the
  contract passes normal execution-contract validation.
- Created the delegated journal run durably at MCP create time.
- Replaced the placeholder supervisor surface with a workspace/run keyed MCP
  registry backed by the delegated journal.
- Added journal rehydration for run status and artifact lookups if the
  in-memory registry entry is absent.
- Wired `delegated_run_start` to launch `IntegratedDelegatedService` as a
  background worker task.
- Added cancellation signaling into the Ollama production worker loop.
- Returned status, checkpoint, event, patch, diff, patch comparison, and final
  review data from real journal or integrated durable state.
- Rejected malformed `runId` values as normal MCP tool errors without panics.
- Corrected `diff.actual` changed-path reporting so final reviews list only
  files that actually changed.
- Added an ignored live Qwen test that starts exclusively through MCP create
  and start, polls MCP status, retrieves MCP events, and retrieves MCP final
  review.
