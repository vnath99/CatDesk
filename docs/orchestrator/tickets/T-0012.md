# T-0012 Delegated Runtime Spike

Status: continued-review
Date: 2026-07-24
Branch: orchestrator/t-0012-feasibility

## Objective

Determine whether an OpenClaw/Ollama delegated worker can use CatDesk as its MCP authority while CatDesk remains the only file and shell execution surface.

## Result

Partially complete, with the main local MCP feasibility risk reduced. CatDesk and Ollama were assessed locally without persistent system changes in the first pass. After the operator installed Node.js and OpenClaw, read-only OpenClaw diagnostics were run and documented. A constrained CatDesk `--headless-mcp` mode was added and probed through OpenClaw disposable config/state. OpenClaw has not been onboarded, no Gateway service has been installed, no providers or credentials were configured, and no model worker run was performed.

## Key Findings

- CatDesk MCP safety behavior is well covered by existing Rust tests.
- Headless local-MCP startup now avoids TUI input, ngrok setup, browser/devtools startup, and hidden random path discovery for orchestration probes.
- Qwen's tool-call support works, but malformed tool results need deterministic validation outside the model.
- OpenClaw has promising orchestration and MCP support, but its native tool authority must be disabled or denied before integration can meet the CatDesk-only authority goal.
- The minimum OpenClaw test posture should allow configured MCP through `bundle-mcp`, deny OpenClaw-native runtime/file/web/browser/automation groups, set `tools.exec.mode: "deny"`, and disable `tools.exec.applyPatch`.
- OpenClaw MCP include filters must be quoted in PowerShell; otherwise comma-separated values can collapse into one bad include string.
