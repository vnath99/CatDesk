# T-0028F: Autonomous Controller

The controller composes the autonomous policy, durable state store,
provider-neutral interface, and independent verifier. It persists `RUNNING`
before a provider turn and `VERIFYING` before the verifier. A terminal provider
response can never produce `COMPLETED_VERIFIED` by itself: a passing independent
verifier, a non-empty authoritative diff, and an independent final-review
artifact are all required.

The controller persists the provider continuity identifier, handle, event
cursor, repair count, cancellation request, and bounded rate-limit deadline.
An in-memory active turn is polled before any resume is considered. After a
restart, only the captured provider session is resumed; a fresh replacement
session is not silently started. Verification failure returns the task to
`QUEUED` for a bounded repair. A provider fault, unavailable final review, repair
budget exhaustion, or prolonged capacity pause writes a bounded escalation
packet and enters `WAITING_FOR_CHATGPT`.

`CodexCliProviderV1` now implements the existing provider-neutral worker seam.
It launches only the directly discovered CLI executable, sends a bounded
contract/history prompt without CatDesk tool definitions, captures the native
Codex thread identifier as soon as the JSONL stream exposes it, and uses that
identifier for later resume. Rate limits are normalized to a safe pause; native
CLI cancellation is used only for a child CatDesk launched and owns.

The controller remains unexposed to MCP until T-0028G. The deterministic tests
cover completion gates, cancellation, continuous polling, restart recovery,
rate-limit backoff/resume, bounded repair, queue progression, and escalation
artifacts.
