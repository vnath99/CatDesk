# T-0024C Worker-Loop Advisory Integration

Status: T-0024C.2 BOUNDARY-HARDENING REVIEW
Date: 2026-07-26

## Objective

Integrate advisory consultation into the worker loop after the T-0024A broker
and T-0024B adapter boundaries have been reviewed.

## Intended Behavior

- CatDesk may request advice after two failed bounded repair attempts.
- CatDesk may request advice for `NEEDS_SUPERVISOR` only when advisory
  consultation is explicitly allowed.
- Returned advice is appended only as untrusted context for the next Qwen turn.
- Qwen must inspect repository state and use ordinary CatDesk tools before
  acting.
- Explicit structured Qwen advice requests remain deferred until there is a
  real structured mechanism; no model-visible advisor tool is exposed.

## Non-Goals

- No provider replacement.
- No fallback-provider behavior.
- No model-visible advisor tools.
- No automatic Git publication.
- No browser-provider authority over repository or execution tools.

## Implementation Status

T-0024C adds the CatDesk-owned Rust process adapter and bounded worker-loop
handoff:

- `DeepSeekProcessAdvisor` starts the standalone Python JSONL sidecar lazily,
  passes a process-scoped authentication token, reserves stdout for protocol
  frames, and redirects diagnostics to stderr.
- The process adapter supports authenticated `hello`, `start`, `status`,
  `advise`, `cancel`, and `shutdown` commands, correlates responses by request
  ID, validates advisor identity, enforces bounded response size, and turns
  timeout, malformed JSONL, wrong IDs, authentication failure, and crash paths
  into bounded advisor failures.
- The execution contract has an optional `advisorPolicy`. Defaults are disabled
  and `LOCAL_ONLY`; enabled policy is restricted to `deepseek-web` with
  `REMOTE_ALLOWED` disclosure.
- Local Python executable, script, selector, and profile paths are supplied only
  by operator-local CatDesk startup environment, not as execution-contract or
  MCP request fields. `advisorLocalConfig` is not part of the MCP schema.
  Configured paths are validated and canonicalized locally. After rehydration,
  the durable policy survives and the runtime is reattached only from the same
  trusted local startup configuration.
- The autonomous worker loop triggers one consultation after the second
  consecutive bounded failed `verify.run` in a failure episode. A later passing
  verification resets the episode.
- Successful advice is appended to the next worker turn only as delimited
  untrusted user context. It is never a system-role message and never grants
  repository, filesystem, shell, Git, patch, verification, job, MCP, browser,
  or provider authority.
- Advisor lifecycle events are journaled with request IDs, status, sizes,
  hashes, selected source paths, timestamps, and existing journal sequence
  allocation. Bounded request/response details are written to local advice
  artifacts and referenced from events.
- Advisor failures are optional by default. `LOGIN_REQUIRED`,
  `TAKEOVER_REQUIRED`, `RATE_LIMITED`, `TIMED_OUT`, `DEGRADED`, `FAILED`,
  malformed protocol, and process crash paths add untrusted unavailable context
  and continue locally unless the policy marks advice as required.
- Required-advice unavailability persists `NEEDS_SUPERVISOR`; the outer MCP
  worker-error handler preserves that durable state and keeps the workspace
  active-run lock instead of overwriting it with `FAILED`.
- Advisor cancellation no longer uses an `Arc<Mutex<DeepSeekProcessAdvisor>>`
  held across a blocking consultation. The process adapter owns the sidecar
  while waiting, polls the CatDesk cancellation flag, sends the JSONL `cancel`
  command promptly, joins the consultation task, suppresses advice delivery
  after cancellation, and keeps one terminal advisor event for the generation.

The released v1 worker, patch, journal, MCP, authentication, provider, and
verification boundaries remain unchanged.

## T-0024C.2 Verification Focus

- MCP schema omits `advisorLocalConfig`.
- Malicious MCP runtime fields are ignored and cannot select an executable or
  adapter script.
- Operator-local runtime config is attached for new and rehydrated runs when
  startup environment is present.
- Missing local runtime leaves the advisor unavailable rather than recovering
  paths from the contract or journal.
- Optional advisor failure continues locally.
- Required advisor failure persists `NEEDS_SUPERVISOR`.
- Blocking sidecar cancellation completes promptly, suppresses completed advice
  delivery, and records exactly one terminal cancellation event.
