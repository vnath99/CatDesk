# T-0028J: Autonomous Loop Acceptance

The end-to-end acceptance scenario requires an operator-local direct Codex
CLI executable configuration before CatDesk can launch an owned child process.
The MCP interface never accepts an executable path and does not read
authentication stores.

Preflight on 2026-08-06 found that the process-scoped
`CATDESK_CODEX_CLI_EXECUTABLE` setting is absent. No Codex worker, provider
turn, disposable fixture, or target workspace was launched. This is a
configuration prerequisite, not evidence of a failed provider capability.

The following deterministic portions are verified locally:

- contract validation, approval hashes, idempotency, path, command, and Git
  policy checks;
- provider-session persistence, bounded retries, rate-limit state, and
  restart-continuity fail-closed handling;
- durable escalation replies, bounded event polling, cancellation reporting,
  and cursor-based MCP control;
- independent command verification, authoritative-diff capture, and final
  review persistence before `COMPLETED_VERIFIED`.

Acceptance remains `BLOCKED` until an operator supplies the process-scoped
executable configuration and authorizes a disposable, credential-free
autonomous Codex CLI run. Once configured, the required run must exercise
verification failure, same-session repair, verified completion, artifact
retrieval, restart recovery, rate-limit handling, escalation/reply,
cancellation, lease expiration, forbidden-operation rejection, duplicate MCP
calls, process crash handling, lost-session escalation, and remote divergence.
