# T-0028B Provider-Neutral Worker Abstraction

Status: implemented

## Objective

Create a provider-neutral lifecycle seam for the autonomous controller without
changing the released Ollama/Qwen delegated-run behavior.

## Delivered

- `ProviderIdV1` accepts only the known `ollama`, `codex-cli`, and `fake`
  provider identities.
- `WorkerProviderV1` exposes capability discovery, provider session creation,
  turn start/resume, cursor-based event polling, cancellation, and health.
- `OllamaWorkerProviderV1` wraps the existing hardened `OllamaAdapter`,
  retaining native tool calls, JSON-envelope recovery, model identity, and
  keep-alive metadata.
- `FakeWorkerProviderV1` provides deterministic lifecycle tests for event
  cursors, same-session resume, and terminal cancellation behavior.

## Compatibility Boundary

The existing integrated delegated loop continues to invoke `OllamaAdapter`
directly. This is intentional: T-0028B adds and tests the abstraction without
changing the current Qwen execution path. T-0028F will move autonomous runs to
the new controller after the Codex adapter, durable state, contracts, policy,
and verification boundaries exist.

The Ollama wrapper reports no in-flight provider cancellation capability. The
current local path remains cancellable at CatDesk turn boundaries. T-0028C will
implement owned-child cancellation for Codex CLI turns.

## Tests

- provider identity parsing and serialization rejects unknown IDs;
- fake turn lifecycle returns events exactly once with a cursor;
- fake resume retains the provider session identity;
- fake cancellation emits a terminal cancellation acknowledgement rather than
  replaying a completion;
- Ollama wrapper preserves local API identity, native tool support, continuity,
  the required Qwen model ID, and keep-alive metadata.

No credential, provider fallback, MCP, Qwen-model, DeepSeek, or delegated-run
policy behavior changed in this ticket.
