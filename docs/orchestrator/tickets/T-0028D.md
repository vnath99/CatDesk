# T-0028D: Persistent Autonomous State

## Objective

Provide a provider-neutral, durable state layer for future autonomous Codex
sessions. The layer is intentionally not wired to the released delegated Qwen
worker or MCP surface in this ticket.

## Storage Model

The later operator configuration will open the store under an operator-owned
directory such as `%USERPROFILE%\\.catdesk\\autonomy`. Each conservative session
slug has separate state, queue, append-only events, provider, verification,
artifact, and lock directories. No credentials, executable paths, MCP routes,
or provider environment values are persisted.

`state.json` and `queue.json` use write, sync, and rename. `events.jsonl` is
append-only and synced after every record. Reads repair only a malformed final
JSONL fragment; a malformed non-terminal record fails closed.

## Safety Semantics

- State and event sequence values are reconciled before a new event is added.
- A session lock is created atomically and may be removed only by the owner
  that created it. There is no broad process or lock cleanup.
- Queue selection requires `READY`, completed dependencies, then highest
  numeric priority with a deterministic task-id tie-breaker.
- A process restart changes an active `RUNNING` or `VERIFYING` session to
  `RECOVERING_AFTER_RESTART` and records an event. It does not launch, resume,
  or replay a provider turn.
- Terminal states must have `active=false`; non-terminal states must have
  `active=true`.

## Deferred Work

T-0028E supplies the versioned autonomous development contract and lease
policy. T-0028F will connect this state store to a controller, validate Codex
session continuity before resume, and decide how a recovered run proceeds.
T-0028G will add the policy-safe MCP management surface.

## Verification

Focused tests cover queue priority and dependencies, invalid queues, atomic
state/event round trips, cursor polling, torn-tail repair, lock ownership, safe
restart recovery, and terminal-state invariants.
