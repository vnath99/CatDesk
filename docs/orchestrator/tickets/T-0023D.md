# T-0023D Functional Release Closure

Status: COMPLETED_VERIFIED

Branch: orchestrator/v1-coding-sprint
Prior ticket commit: 5345a1f

## Objective

Close the v1 functional release target without adding new architecture or
optional features:

ChatGPT Web or an external MCP client -> authenticated loopback CatDesk MCP ->
validated `ExecutionContractV1` -> one durable delegated run ->
CatDesk-owned worker loop -> local Ollama/Qwen -> CatDesk
read/search/patch/verify/diff tools -> verified completion or safe failure.

## Scope Completed

- Added process-scoped bearer-token authentication for headless MCP. The token
  is required through `--auth-token` or `CATDESK_MCP_AUTH_TOKEN`, validated for
  length, and redacted from ready output.
- Preserved loopback-only headless binding and tested the real Axum HTTP MCP
  server through a separate `reqwest` client.
- Published a bounded `ExecutionContractV1` input schema through
  `tools/list`, including provider policy, approvals, expected artifacts, and
  path constraints.
- Made malformed MCP inputs and malformed contracts return bounded MCP tool
  errors instead of panics.
- Enforced one active delegated run per workspace in the supervisor registry.
- Added `delegated_run_approve_start` and implemented only the v1 RunStart
  approval flow. Approvals are tied to one run/request, expire, and are
  consumed once.
- Failed closed when contracts require unsupported approval categories such as
  tool exceptions, unrestricted shell, Git push, or merge.
- Restricted starts to valid states, rejected terminal/already-running starts,
  and rehydrated orphaned running journal states as `NEEDS_SUPERVISOR`.
- Added `CANCEL_REQUESTED` so cancellation is requested first and becomes
  `CANCELLED` only after worker acknowledgement.
- Bounded provider input history and compacted older turns into a checkpoint
  summary that retains objective, scope, acceptance criteria, latest patch,
  latest verification, latest diff, and remaining tool budget.
- Ensured tool results are sent once in provider history.
- Added a completion gate requiring an explicit completion claim, passing
  verification, authoritative diff evidence, supported acceptance criteria,
  allowed changed paths, and no unresolved `OUTCOME_UNKNOWN` actions.
- Replaced patch identity hashes with SHA-256 content/snapshot hashes.
- Required pre-image and base snapshot validation before patch apply.
- Rejected final symlink and Windows reparse-point targets.
- Kept v1 patch application to one file per patch; multi-file work remains
  sequential through separately journaled patches.
- Applied file mutations with temporary-file-plus-atomic-replace.
- Included tracked and untracked file changes in final diff evidence.
- Added torn-final-JSONL-record recovery while preserving earlier malformed
  journal records as hard errors.
- Populated structured run events with run ID, worker-session ID, turn ID, item
  ID, tool-call ID, patch ID where applicable, and ordered sequence values.
- Updated local and dev orchestrator startup scripts to generate an ephemeral
  auth token and pass it into headless MCP startup.

## Remaining Boundaries

- No automatic commit, push, pull request, merge, release, deployment, or
  publication is performed by delegated runs.
- Only local Ollama/Qwen is supported for the v1 functional release path.
- One active run per workspace is supported.
- One structured tool call per model turn is supported.
- One file per patch application is supported; sequential multi-file work is
  intentionally modeled as separate patches.
- Pause/steer remains deferred beyond the cancellation-safe boundaries shipped
  here.
- Browser automation, provider fallback, OpenClaw, dashboards, parallel
  agents, generalized plugin systems, advanced indexing, service installation,
  and broad approval workflows remain prohibited/deferred for this ticket.
