# T-0024B Browser Advisor Adapter

Status: IMPLEMENTED_LOCAL_T-0024B.4
Date: 2026-07-25

## Objective

Prototype a standalone browser-backed advisor adapter after T-0024A review.

## Scope Completed

- Added a standalone experimental DeepSeek web advisor adapter.
- Added authenticated JSON Lines stdin/stdout protocol.
- Added selector configuration outside the core adapter logic.
- Added a lazy SeleniumBase CDP launch path with dedicated profile directory.
- Added explicit adapter states:
  `STOPPED`, `STARTING`, `LOGIN_REQUIRED`, `READY`, `SENDING`,
  `WAITING_FOR_RESPONSE`, `COMPLETED`, `RATE_LIMITED`, `TAKEOVER_REQUIRED`,
  `TIMED_OUT`, `CANCELLED`, `DEGRADED`, `FAILED`.
- Added completion detection that combines response-container count, stop/send
  button state, text stability, and timeout without magic toolbar words.
- Added redacted diagnostics.
- Added deterministic offline tests with synthetic HTML fixtures.
- Added T-0024B.1 standalone advisory turn:
  request validation, exact-origin check, bounded prompt construction,
  one-time prompt submission, baseline-aware newest-response extraction,
  authenticated cancellation, and protocol-only stdout handling.
- Added T-0024B.2 standalone safety controls:
  worker-threaded JSONL advice execution, responsive status/cancel/shutdown,
  one-active-request enforcement, disclosure enforcement, fixed DeepSeek origin
  allowlist, partial startup cleanup, prompt clearing before insertion, and
  bounded browser-operation failure responses.
- Added T-0024B.3 standalone live-site reliability controls:
  exact reject-first cookie banner selectors, paced typing with cancellation
  and timeout, visible newest-response completion tracking, visible provider
  rate-limit selectors, stale/empty/baseline response rejection, strict
  terminal-event consistency, explicit env-login option, CAPTCHA/Turnstile
  takeover detection, and exact configured chat-name selection.
- Added T-0024B.4 standalone live interaction correction:
  redacted live selector calibration, precise composer/send selectors,
  submission-confirmation diagnostics, no magic-word completion dependency,
  bounded input-event paced typing, newest-response-only extraction, cookie
  handling result capture, and immediate process-environment credential
  scrubbing after opt-in env-login reads.
- Added isolated experimental SeleniumBase setup pin.

## Required Boundaries

- Prefer SeleniumBase CDP mode.
- Use a dedicated persistent browser profile.
- Prefer manual/persistent login; allow env-login only through explicit
  `--allow-env-login` and process-scoped credentials.
- Return `TAKEOVER_REQUIRED` for CAPTCHA or security verification.
- Communicate through a narrow authenticated local protocol.
- Expose no repository, filesystem, shell, Git, patch, verification, job, MCP,
  or CatDesk tool authority.

## Explicitly Forbidden

- Plaintext credentials.
- Login automation.
- CAPTCHA-clicking or security-bypass behavior.
- Hard-coded account or conversation data.
- Generated CSS-class selectors as a stable API.
- Infinite keep-alive loops.
- CAPTCHA or Turnstile solving/clicking automation.

## Implementation Status

Implemented as a standalone experimental adapter only. It is not connected to
the CatDesk `AdvisorBroker` or released worker pipeline in T-0024B.

Live DeepSeek smoke testing remains opt-in and headed with manual login. It is
not connected to the CatDesk `AdvisorBroker` or released worker pipeline.

## T-0024B.2 Live Smoke Result

The opt-in headed smoke used a dedicated `.tmp` Chrome profile and synthetic
advisory data. The adapter reached `READY`, accepted an advice request, emitted
a correlated bounded `RATE_LIMITED` result, accepted a second synthetic
request, returned `cancel` with `ok: true`, and shut down cleanly. The smoke did
not provide CatDesk tool definitions, repository content, credentials, cookies,
or execution authority to the browser advisor.

## T-0024B.3 Live Smoke Requirement

The T-0024B.3 headed synthetic smoke validates: start, persistent/manual login
or explicit env-login, cookie handling, `READY`, one synthetic completed
response, no early second request, JSONL cancellation with exactly one
`CANCELLED` terminal result, refresh back to `READY`, and clean shutdown. If the
account is genuinely rate-limited, the adapter must report `RATE_LIMITED` and
stop without aggressive retries.

Observed local result: `READY` succeeded, the first synthetic request was
accepted, the too-early second request was rejected with
`ADVICE_ALREADY_ACTIVE`, and shutdown was clean. The first request returned
`TIMED_OUT` with no visible assistant response, so the cancellation leg was not
run. This is preserved as live-site evidence rather than retried aggressively.

## T-0024B.4 Live Smoke Result

The T-0024B.4 headed synthetic proof used the existing dedicated persistent
Chrome profile and submitted one harmless synthetic advisory request. The
adapter reached `READY`, accepted the request, and shut down cleanly. Redacted
structural evidence showed:

- origin was `https://chat.deepseek.com`;
- cookie banner state was `absent`;
- the configured composer was `textarea.ds-scroll-area`;
- paced input-event insertion changed the composer value and enabled the
  configured send control;
- after the terminal timeout, the composer was empty, no configured
  stop/generation control was visible, no configured rate-limit/error selector
  was visible, and the adapter found zero visible assistant/user conversation
  blocks to extract.

The live request therefore ended `TIMED_OUT`, not `COMPLETED`. Because no
assistant response could be located, no further live request was submitted and
no additional heuristics were added blindly. The adapter remained fail-closed:
it did not return the submitted prompt, old page content, an empty response, or
a parent whole-conversation container as advice.
