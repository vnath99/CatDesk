# T-0030: Codex-first local-Qwen fallback — Phase 1

Status: implemented pending CatDesk independent verification

## Implemented behavior

CatDesk continues to prefer the authenticated local `codex-cli` worker. A
bounded classifier separates transient 429/capacity messages from explicit
plan/credit exhaustion. Transient limits retain the existing Codex session,
backoff, and same-thread repair path.

On an explicit credit/allowance signal, CatDesk writes a bounded durable
handoff before attempting only the configured local Ollama/Qwen worker. The
handoff preserves the logical task, ordered steps, constraints, completed
task IDs, remaining budgets, opaque Codex thread provenance, and bounded
verification state. It contains no auth data, browser state, environment
values, or raw provider transcript.

If the selected Qwen model is not locally healthy, CatDesk records
`QWEN_UNAVAILABLE` and waits for ChatGPT. The route has no API, browser,
DeepSeek, paid, or cloud candidate. A safe future task boundary can return to
Codex without interrupting an active Qwen turn.

## Phase 1 limitations

- The controller's autonomous Codex CLI live acceptance still requires the
  operator-local executable prerequisite documented in T-0028J.
- The handoff stores controller-level completed tasks and bounded provenance;
  richer tool-journal replay evidence remains owned by the existing
  provider-router/journal layer and is a Phase 2 integration target.
- Codex restoration is re-evaluated only at safe task boundaries; reset-time
  probing and multi-task planner advancement are intentionally deferred.

## Phase 1B review correction

Phase 1 originally passed an empty CatDesk tool-definition list to both
providers and did not dispatch normalized local-Qwen tool calls from the
autonomous controller. Phase 1B corrects this by routing active local-Qwen
calls through the existing integrated bounded tool service and its journal.
Only the autonomous-contract-filtered read/search/patch/verify/diff surface is
given to Qwen; `CodexCliProviderV1` still receives no CatDesk definitions.
Qwen completion claims are gated on CatDesk-recorded verification and diff
evidence before the independent controller verifier may run. The review bundle
contains deterministic disposable-fixture evidence and records that no live
Ollama smoke was run.

## Invariants

- `allowPaidFallback=false` and `allowCloudFallback=false` remain required by
  contract validation.
- Ollama endpoint configuration accepts loopback HTTP addresses only.
- CatDesk verification, authoritative diff capture, and final review remain
  mandatory before `COMPLETED_VERIFIED`.
