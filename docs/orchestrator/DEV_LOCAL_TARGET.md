# Ordinary developer local target: read-only planning

2026-11-04. This sibling facade preserves the existing `catdesk-dev-lane.ps1`, its actions and nine-field receipts. It is not a release, recovery, runtime or cache-management subsystem. The general CatDesk goal remains paused; this source work has separate resource-prevention authorization.

From the source checkout, run `& .\scripts\catdesk-dev-local-target.ps1 plan`. This read-only command proposes a future target below the actual Windows Known Folder LocalAppData: `CatDeskDev\ordinary-targets-v1\<workspace-key>\<recipe-key>\target`. It does not create that location, acquire a writer lease, write a marker, invoke Cargo, adopt an existing target or change configuration. It emits its own versioned JSON; a proposal is not execution authorization.

The Windows metadata adapter opens existing ancestry components with explicit OPEN_NO_RECALL and OPEN_REPARSE_POINT, and retains their handles without delete sharing through observation. Both flags apply to every metadata/data open; there is no fallback. It checks canonical final paths, fixed local volume, physical file IDs, current-user ownership of the workspace/LocalAppData/tool files, and rejects offline/recall/unpinned components. It refuses unexpected Known Folder redirection. Attribute-only inspection precedes data access; tool and lock hashes are read through retained non-writable handles after a second physical identity check. Cargo configuration is checked for existence only; its contents are never read. Unknown configuration or inherited Cargo/tool redirects produce ATTENTION. An already loaded different native adapter template is refused. Reports contain fixed categories and hashed keys, with no absolute paths, owner SID, configuration content or arbitrary exceptions. These are planning checks, not owner-only ACL or complete compiler-runtime provenance qualification.

The workspace key binds physical worktree identity and owner. The candidate recipe key binds cargo.exe, rustc.exe, Cargo.lock, intended host/target, profiles/features and policy. It does not cover compiler DLLs, the linker, the complete toolchain closure or effective build parity; those must be independently qualified before any future execution or reuse. Commit is evidence per observation, not a directory key. A source edit without a candidate recipe change proposes the same namespace. A changed candidate proposes a different namespace but never initializes it. Any existing `CatDeskDev` namespace is HOLD; no owner manifest or historical completion is inferred from its age, PID, unlocked files or a reboot.

## Execution is deliberately unavailable

`build` and `verify` emit a refusal receipt and terminate with `DEVELOPER_TARGET_EXECUTION_OWNER_UNQUALIFIED` before loading the native adapter or manipulating any target. Neither is an executable build path in this version.

The existing ordinary `WakeRepairContainedProcess.Run` returns root exit/timeout information and closes its Job; it does not report whole-Job quiescence plus output EOF/drain. Its process starts before assignment. Those observations cannot support a crash-safe target-reuse OUTCOME. This version does not alter that helper, attach release authority to its result, or manufacture a terminal target record.

Before implementing execution, a separately reviewed ordinary owner must prove suspended-before-assignment containment, explicit fixed executable/environment/cwd, bounded concurrent pipe drainage, whole-Job zero-process completion while owned handles and the target lease remain held, and honest timeout/unknown handling. The target protocol still needs a full-operation exclusive lease, bounded immutable START/OUTCOME, exact selected binary hash binding, refusal of unresolved prior runs, explicit target argv, incremental=0 for both build and verify, and environment/cwd restoration. No existing target may be copied, moved, shared, pruned or silently adopted. No new Cargo home, dependency-cache sharing, global setting or protected-worker change is part of this work.

## 2026-11-04 ordinary owner preparation: no native entry point

`catdesk-dev-local-target-owner.ps1` currently defines only pure input-preparation functions: Windows argument quoting, bounded explicit Unicode environment encoding, the four fixed future Cargo operation recipes, and an unavailable-owner contract. Dot-sourcing defines functions without compiling or launching anything. The preparation object is mutable data, not an admission capability, path verification, native observation, target lease or completion witness. No native Run implementation is present, and the existing facade still refuses build/verify.

The proposed synchronous pipe loop was rejected before implementation. Microsoft warns that [PeekNamedPipe can block with synchronous handles in a multithreaded application](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-peeknamedpipe); [anonymous pipes do not support overlapped I/O](https://learn.microsoft.com/en-us/windows/win32/ipc/anonymous-pipe-operations). Pure policy checks cannot establish a finite native drain in a PowerShell/.NET host.

The pending alternative is one private local byte named pipe per output stream, with an asynchronous server/read endpoint and synchronous child/write endpoint. Its design requires a single pending read per stream, nonblocking completion observation, real EOF, bounded retained output with continued drainage, creation-time Job ownership and restricted handle inheritance. Cancelling I/O is not completion. Pending OVERLAPPED storage, buffers, events and handles must stay alive until completion is proved. A fixed-capacity, strongly rooted attention owner would deny all new operations and retain UNKNOWN/HOLD on unresolved I/O; it would bound retained allocation and caller return, not guarantee cleanup latency or an absolute kernel/AV/provider deadline. There is no background recovery monitor, scheduler or automatic reuse in this proposal. The full process integration remains unqualified. The separately admitted output component results below do not qualify a child executor or target reuse.

The independently reviewed contract also requires private random first-instance pipe names, remote-client rejection, a protected current-user DACL, confirmed connection before resume, and inheritance of only child writers plus approved stdin. A [successful zero-byte pipe read can reflect a zero-byte write](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile), so it is not EOF. Neither root exit, Job0 nor cancellation proves closed writers. [GetOverlappedResult with a false wait argument reports incomplete pending operations](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-getoverlappedresult); [CancelIoEx success or ERROR_NOT_FOUND is not completion certification](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex). Any attention owner must be reserved before I/O and strongly rooted outside runspace disposal, finalizers and version reload, with a strict resource cap. A dedicated one-shot worker might reduce reusable-host risk but adds a process/ownership protocol requiring separate scope; an unconfirmed exit must hold admission, never launch a replacement. No worker or harness is implemented here.

The initial 43-case Core run preceded a peer finding: cumulative environment size was checked after collecting entries. A new regression reproduced that late refusal. The corrected builder reserves the final NUL and checks the cumulative name/value/equals/NUL size before each insertion, stopping before any later entry on overflow. Final unchanged source passed 47 pure cases on Core 7.6.5 and 47 on Desktop 5.1, including exact boundaries, early getter refusal and empty double-NUL preservation. No native compilation or child fixture ran. Version-bound evidence is in `docs/verification/DEV_LOCAL_TARGET_OWNER_PREPARATION_2026_11_04.json`. A future native fixture admission must identify the exact resident test executable/hash, immutable tiny child fixture, finite parent harness and fresh resource/ownership window. Its matrix must cover pre-resume Job membership, immediate descendants, restricted handles, root exit before descendants/EOF, simultaneous pipe saturation, actual exit codes, timeout, incomplete cancellation, bounded quarantine, fault injection and cleanup. No malformed-image launch, real Cargo, external target initialization or process-control action is authorized by this source work.

## 2026-11-04 output dependency: managed tests and bounded native cases

`scripts/catdesk-dev-local-target-output.ps1` is a define-only library initializer. Explicit initialization compiles its C# in a Core host; loading the script does not initialize a backend or open I/O. It has no child-process, Job, workspace, Cargo, lease, browser, runtime-control or recovery entry. Its native backend has only the three bounded same-process observations below; full failure and process integration qualification remains open. The existing build/verify refusal remains unchanged.

The component source reserves one fixed process-global strong-root slot before endpoint setup. Two private local output channels each retain one 16 KiB read buffer, one OVERLAPPED/manual-reset event and at most one pending operation; each capture retains at most 16 KiB while continuing to drain. Nominal data buffers total 64 KiB before optional frozen-prefix access, at most 96 KiB including two cached prefix copies; this is not a process-RSS limit. Native setup proposes first-instance byte pipes, remote rejection, explicit protected current-user DACL/readback and noninheritable own server/client handles. Observations contain only fixed states, counts and confidence flags; they are read-only and grant no execution or target reuse.

Cancellation observes existing operations but must never issue another read. Normal completion after cancellation still contributes already-issued bytes. Zero-byte success and settled cancellation are distinct from closed-writer EOF. Pending cancellation/query/cleanup uncertainty retains storage and poisons the fixed process gate after a finite grace, denying new pairs without disposal, version-reset bypass or background cleanup. An uncertain close is latched before the attempt and must never retry that raw handle. This bounds retained component resources, not native-call or kernel cleanup latency. It is not safe cache reuse or a replacement for the eventual owned-Job/lease/journal integration.

`GetCaptured(channel)` is proposed bounded diagnostic access only after the capture is settled or quarantined. Active access is refused. It returns one cached read-only copy of that channel's known managed prefix, not the possibly pending native read buffer. Quarantine data remains partial and grants no completion or reuse authority. Callers must treat diagnostics as potentially private and must not publish arbitrary captured output.
